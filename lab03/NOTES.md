# Воркшоп по Git

## 1. Создание состояний проекта

### Первый коммит
Команда:
`git add lab03/calc.py`
`git commit -m "added base addition for calculator"`

Что сделала:
Создала начальную версию калькулятора со сложением двух чисел.

### Второй коммит
Команда:
`git add lab03/calc.py`
`git commit -m "Add subtraction to calculator"`

Что сделала:
Добавила в калькулятор операцию вычитания.

### Третий коммит
Команда:
`git add lab03/calc.py`
`git commit -m "Add multiplication to calculator"`

Что сделала:
Добавила в калькулятор операцию умножения.

## 2. Сравнение версий и поиск изменений

### git log --oneline --stat

Команда:
`git log --oneline --stat`

Показывает историю коммитов в сокращённом виде и статистику изменений файлов в каждом коммите.

### git diff

Команда:
`git diff HEAD~2 HEAD -- lab03/calc.py`

`git diff` показывает различия между двумя состояниями файлов. В данном случае сравнивается версия calc.py два коммита назад с текущей версией.

### git show

Команда:
`git show HEAD~1`

`git show` показывает информацию о конкретном коммите и изменения, которые этот коммит внёс.

### Отличие git diff от git show

`git diff` используется для сравнения двух состояний и показывает различия между ними.

`git show` используется для просмотра конкретного коммита: его информации и внесённых им изменений.

### git log -S

Команда:
`git log -S"def" --oneline -- lab03/calc.py`

Команда ищет коммиты, в которых изменилось количество вхождений указанной строки.

В моём calc.py строка `def` не использовалась, поэтому поиск не нашёл соответствующих изменений.

### git blame

Команда:
`git blame lab03/calc.py`

Показывает, каким коммитом и когда была изменена каждая строка файла. Это позволяет определить происхождение отдельных строк.

## 3. Восстановление файла

### git restore

Команда:
`git restore lab03/calc.py`

Восстанавливает файл до состояния последнего коммита.

Если в файле были несохранённые изменения, они будут потеряны.

### git restore --source

Команда:
`git restore --source=HEAD~2 lab03/calc.py`

Восстанавливает файл из указанного старого состояния, в данном случае из коммита HEAD~2.

После этого файл отличается от текущего состояния, но это изменение ещё не является коммитом.

Команда:
`git diff`

Показывает различия между восстановленной старой версией и текущим состоянием.

Повторная команда:
`git restore lab03/calc.py`

Возвращает файл к состоянию последнего коммита.

## 4. Ошибочный коммит и его отмена

В calc.py была добавлена операция деления без проверки деления на ноль.

Команда:
`git commit -am "Add unsafe division"`

После этого ошибка была отменена командой:

`git revert HEAD`

`git revert` не удаляет ошибочный коммит из истории. Он создаёт новый коммит, который отменяет изменения предыдущего коммита.

`git reset --hard` перемещает указатель текущей ветки и может удалить изменения из рабочей директории и истории текущей ветки.

Для опубликованной истории безопаснее использовать `git revert`, потому что история сохраняется и появляется отдельный коммит, отменяющий ошибочные изменения.

## 5. Тег рабочей версии

Команда:
`git tag -a v1.0 -m "Рабочая версия калькулятора"`

Тег `v1.0` отмечает конкретное состояние проекта и позволяет обращаться к этому коммиту по постоянному имени.

Команды:
`git tag`
`git show v1.0`

Первая показывает существующие теги, вторая показывает информацию о версии, отмеченной тегом.

Тег отличается от ветки тем, что тег обычно используется как постоянная метка определённой версии, а ветка продолжает двигаться вместе с новыми коммитами.

## 6. Эксперимент в ветке

Команда:
`git switch -c experiment`

Создаёт новую ветку experiment и переключается на неё.

Изменения в эксперименте выполняются отдельно от main.

Команда:
`git commit -am "Add safe division"`

Сохраняет экспериментальное изменение отдельным коммитом.

Команда:
`git switch main`

Возвращает меня в основную ветку.

Команда:
`git merge --no-ff experiment`

Вливает экспериментальную ветку в main и создаёт отдельный merge-коммит.

Команда:
`git branch -d experiment`

Удаляет уже слитую экспериментальную ветку.

Преимущество работы в отдельной ветке в том, что неудачный эксперимент можно удалить, не изменяя main.
## 5. Тег v1.0

Команда:
`git tag -a v1.0 -m "Рабочая версия калькулятора"`

Тег — это имя, привязанное к определённому коммиту. В отличие от ветки, тег обычно используется для обозначения важной версии проекта и не перемещается при появлении новых коммитов.

Команда `git tag` показывает существующие теги.

Команда `git show v1.0` показывает коммит и изменения, на которые указывает тег.
